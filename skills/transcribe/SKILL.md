# transcribe

Локальная транскрибация той же моделью, что стоит в Handy (parakeet-tdt-0.6b-v3), через `parakeet-mlx`. Правило: **для транскрайба всегда модель из Handy**, ничего нового не качать без причины.

## Основной путь (Parakeet, модель Handy)

```bash
# 1. Нормализация — ОБЯЗАТЕЛЬНА для записей встреч с телефона (тихий звук):
ffmpeg -y -v error -i "<вход>" -ar 16000 -ac 1 -af "highpass=f=80,dynaudnorm=f=150:g=15" /tmp/<имя>_norm.wav

# 2. Транскрибация (txt + srt + vtt + json):
parakeet-mlx /tmp/<имя>_norm.wav --model mlx-community/parakeet-tdt-0.6b-v3 \
  --output-format all --output-dir <куда> --output-template <имя>
```

- MLX-веса модели скачиваются в HF-кэш один раз при первом запуске.
- Длинные файлы (час+) обрабатывает сам, чанкует.
- Языки: русский + 24 европейских. Файлы >5 мин гонять в run_in_background.
- ONNX-файлы самого Handy (`~/Library/Application Support/com.pais.handy/models/`) напрямую не читаются parakeet-mlx — это тот же чекпоинт в MLX-формате, это и есть «модель из Handy».

## Какую модель брать — решать ДО прогона

Parakeet не универсален. Он быстрый и никогда не зацикливается, но на плохом звуке
**тихо недослышивает**: не падает, не ругается, отдаёт связный текст, из которого
пропали целые куски.

| Источник звука | Чем гнать |
|---|---|
| Диктофон близко, один-два голоса, OBS, звонок | Parakeet — быстро и достаточно |
| **Запись из зала, лекция, собрание, много людей, телефон в кармане** | **Сразу whisper по кускам** (ниже) |

Проверено 03.09.2026 на записи орг собрания 126 мин, телефон в зале на 20 человек:
parakeet выбросил из реплики говорящего целый абзац в четыре предложения и превратил
«можно с ума сойти» в «можно с массовитим». Текст при этом читался гладко — потерю
видно только при сверке с whisper.

**Гоняй обе модели, если запись важная.** Сверять не по словам, а по фактам: даты,
числа, кто что сказал. Совпало у обеих — можно опираться; разошлось — переслушать кусок.

## Whisper (whisper.cpp) — для сложного звука

Модели лежат в `~/.cache/whisper/` (ggml-large-v3-turbo-q5_0.bin + ggml-silero-v5.1.2.bin).

**Никогда не гонять длинный файл одной командой.** Только через скрипт:

```bash
python3 ~/.claude/skills/transcribe/scripts/whisper_chunked.py \
  /tmp/<имя>_norm.wav <куда> <имя>            # по умолчанию куски 10 мин
```

Он режет вход, гонит каждый кусок отдельным файлом, считает повторы внутри куска,
залипшие автоматически перегоняет по 150 сек и сшивает всё со сдвигом таймкодов.
На выходе `<имя>.txt` и `<имя>.srt`.

Для короткого фрагмента (проверить одно место, вытащить цитату) — напрямую, это безопасно:

```bash
ffmpeg -y -v error -ss <начало_сек> -t <длина_сек> -i /tmp/<имя>_norm.wav /tmp/spot.wav
whisper-cli -m ~/.cache/whisper/ggml-large-v3-turbo-q5_0.bin -f /tmp/spot.wav -l ru
```

## Грабли (проверено 21.07.2026)

- **Whisper зацикливается** («Продолжение следует…» на весь файл). Раньше здесь было написано, что виновата тишина и лечит `-nc` — **это неверно, см. блок 03.09.2026**.
- Прежде чем гнать весь файл, быстрый smoke-тест: вырезать 45 сек с громкого места (`ffmpeg -ss <t> -t 45`), убедиться что распознаётся речь. Громкие места искать: `ffmpeg -i f.wav -af volumedetect -f null -` по сэмплам.
- Выход проверять по `wc -w`: у часовой встречи ожидаемо 5–9 тыс. слов. Сотни слов = что-то сломалось. **`wc -w` НЕ ловит зацикливание** — см. ниже.

## Грабли (проверено 03.09.2026, запись собрания 126 мин)

- **`-nc` в этой сборке whisper-cli не существует.** Команда просто печатает справку
  и выходит с кодом 1, а фоновая задача рапортует «failed» без внятной причины.
  Аналог называется `-mc N` / `--max-context N` (0 — не хранить контекст).

- **Зацикливание вызывает ДЛИНА файла, а не тишина.** Тот же кусок, вырезанный
  в отдельный файл на 200 сек, распознаётся начисто — и с `-mc 0`, и без него,
  и с `--vad`, и без. Внутри длинного файла он же уходит в петлю. Замеры на одной записи:

  | прогон | слов | уникальных строк из всех |
  |---|---|---|
  | весь файл, без флагов | 15 010 | 873 из 5465, одна фраза ×3215 |
  | весь файл + `--vad` | 16 406 | 1957 из 4258, одна фраза ×1949 |
  | нарезка по 10 мин | 14 171 | 2109 из 2238, чисто |

  VAD уменьшает петлю вдвое, но не убирает. Лечит только нарезка.

- **Whisper на петле дописывает несуществующее.** В выход попадают «Субтитры сделал
  DimaTorzok», «Спасибо за субтитры Алексею Дубровскому» — модель обучалась на
  субтитрах и в отсутствие сигнала галлюцинирует концовку ролика. Если такое
  встретилось в тексте — весь кусок недостоверен.

- **Проверять выход счётчиком повторов, а не объёмом.** Зациклившийся файл выглядит
  нормальным по `wc -w` — слов даже больше. Ловится так:

  ```bash
  python3 -c "
  import collections,sys
  L=[l.strip() for l in open(sys.argv[1],encoding='utf-8') if l.strip()]
  c=collections.Counter(L)
  print('строк',len(L),'уникальных',len(set(L)))
  for s,n in c.most_common(3): print(f'{n:>5}x {s[:60]}')
  " <файл>.txt
  ```
  Уникальных меньше половины строк — переделывать.

- **Нарезка не чинит быструю речь.** Если человек тараторит, оба движка дадут разное
  и оба неверно. Такие места помечать как неразборчивые и переспрашивать,
  а не подставлять правдоподобное: цитаты в артефактах должны быть из данных.

## Грабли (проверено 22.08.2026)

- **Нет сети до HF → загрузка модели падает, хотя она в кэше.** Симптом:
  `Error loading model mlx-community/parakeet-tdt-0.6b-v3: [Errno 2] No such file
  or directory: 'mlx-community/parakeet-tdt-0.6b-v3/config.json'` — библиотека не
  смогла резолвнуть репозиторий и стала читать его имя как локальный путь.
  Фолбэка на кэш нет, `HF_HUB_OFFLINE=1` **не помогает**.

  Лечение — передать путь к снапшоту напрямую:
  ```bash
  snap=~/.cache/huggingface/hub/models--mlx-community--parakeet-tdt-0.6b-v3/snapshots/*
  parakeet-mlx "<файл>.wav" --model $(echo $snap) --output-format all \
    --output-dir <куда> --output-template <имя>
  ```
  Проверить, что модель на месте: `find ~/.cache/huggingface/hub -name config.json`
  внутри `models--mlx-community--parakeet-tdt-0.6b-v3`.

- **Для записей с OBS нормализация почти ничего не меняет.** На 50-минутной
  записи звонка: без нормализации 6254 слова, с ней 6243, тексты совпадают на
  94,5%. Канон из шага 1 рассчитан на диктофон в кармане (там звук тихий и
  скачет), у экранной записи уровень изначально ровный. Шаг не пропускать — он
  бесплатный и на плохом звуке спасает, — но и не ждать от него чуда.

- **`nohup ... &` + фоновый Bash: «команда завершилась» ≠ «транскрибация
  завершилась».** Уведомление приходит про обёртку, а parakeet продолжает
  работать. Проверять `pgrep -f parakeet` и наличие выходных файлов, а не статус
  задачи. 50 минут аудио на M3 — около двух минут работы.

## После транскрибации

Спикеры не размечаются — восстанавливать по контексту реплик. Для разбора встречи:
прочитать txt целиком, srt использовать для таймкодов цитат.

### Если нужна разметка спикеров

Ни parakeet, ни whisper этого не умеют в принципе — это отдельная задача (диаризация)
и отдельная модель. Что есть локально под Apple Silicon, если понадобится:

- **[trailofbits/scribe](https://github.com/trailofbits/scribe)** — ближе всего к нашему
  стеку: parakeet-mlx + диаризация через CoreML, модели тянутся сами, аккаунт не нужен.
  Первый кандидат, если задача возникнет всерьёз.
- **[speech-swift](https://github.com/soniqo/speech-swift)** / FluidAudio — Swift + Neural
  Engine, pyannote или Sortformer. Быстро, но у Sortformer жёсткий потолок в 4 спикера —
  для зала не годится.
- **pyannote community-1 + WeSpeaker** через MLX — под неизвестное число спикеров,
  ~32 МБ моделей. Длинные записи резать кусками, иначе память улетает.

Стандартный приём — гнать ASR и диаризацию независимо и сшивать по таймкодам,
а не искать движок, который делает всё сразу.
