# blog-search — поиск по своему блогу

Локальный семантический поиск по `src/content/blog/*.md`. Эмбеддинги
(OpenRouter `text-embedding-3-small`, 1536 dims) + cosine similarity.
Ищет по **смыслу**: запрос «выгорание» находит пост «Отдыхать не получается»,
в котором слова «выгорание» нет вообще.

**Рабочая директория для всех команд:** `~/cursor/pioblog/mcp/blog-search`

## Главный путь — CLI

```bash
cd ~/cursor/pioblog/mcp/blog-search && node cli.mjs <команда>
```

CLI не имеет зависимостей — только встроенные модули Node и `fetch`.
Это осознанный выбор: MCP-сервер требует `@modelcontextprotocol/sdk` и
падает, если `node_modules` снесли (так и произошло 01.08.2026 — MCP
показывал `✗ Failed to connect` неизвестно сколько времени). CLI в такой
ситуации продолжает работать.

| Команда | Что делает |
|---|---|
| `search "<запрос>"` | Семантический поиск. `--tag T` `--limit N` `--full` `--min 0.35` |
| `similar <slug>` | Похожие посты. Вектор берётся из индекса — **API не дёргается вообще** |
| `tags` | Все теги с количеством постов |
| `tag <имя>` | Посты тега. `--coherence` — связность и тематические выбросы |
| `get <slug>` | Полный markdown поста. `--meta` — плюс frontmatter |
| `check` | Свежий ли индекс. Без запросов к API, ~100 мс |
| `sync` | Досбор индекса (инкрементально) |

`--json` у любой команды → машиночитаемый вывод. Используй его, когда
результат идёт в дальнейшую обработку, а не человеку на экран.

### Про индекс: руками синкать не надо

`search` и `similar` перед работой сами сверяют хэши постов с индексом и
дособирают расхождение. Проверка бесплатна (чтение файлов, без API),
досбор 13 постов занял 1.4 с. Если индекс обновился, в выводе появится
строка `ℹ индекс обновлён: +N новых…` — это норма, не ошибка.

Сверка идёт по контентному хэшу, а не по количеству: отредактированный
пост тоже переиндексируется.

`sync` вручную нужен только чтобы прогреть индекс заранее — например,
перед серией запросов.

## Про MCP: по умолчанию не использовать

В сессии могут быть тулы `mcp__blog-search__search_posts` / `list_by_tag` /
`get_post`. Соблазнительно взять их как более короткий путь — но у них есть
изъян, который не виден по выдаче.

MCP-сервер читает `index.json` **один раз при старте процесса** и больше
никогда его не перечитывает (`server.mjs`, загрузка на старте). Отсюда два
следствия: он не досинкивает новые посты, и он не увидит индекс, который
обновил CLI, пока сервер не перезапустят. Выдача при этом выглядит
совершенно нормальной — просто без свежих постов.

Поэтому дефолт — CLI. К MCP имеет смысл идти, только если нужен один
быстрый взгляд и заведомо известно, что новых постов с момента старта
сессии не появлялось. Если MCP-тулы отсутствуют или падают — это не
проблема, **не чини их на ходу**, просто работай через CLI.

Починить MCP, когда дойдут руки: `cd ~/cursor/pioblog/mcp/blog-search && npm install`
(типовая причина падения — снесённые `node_modules`).

## Рецепты

### 1. «Писал ли я уже про X?»

Основной вопрос перед новым постом. Задача — не только найти, но и сказать
честно: это дубль или новый угол.

```bash
node cli.mjs search "<тема>" --limit 8 --json
```

Как читать score (cosine): выше `0.45` — очень близко, вероятен дубль;
`0.35–0.45` — та же область, стоит перелинковать; ниже `0.30` — тема
свободна. Пороги эмпирические, не абсолютные — смотри на заголовки.

Отвечай так: есть/нет дубля → какие посты ближе всего с датами → что из
них стоит процитировать или перелинковать в новом посте.

### 2. Подборка по теме (рассылка, дайджест)

```bash
node cli.mjs search "<тема>" --limit 15 --full --json
```

`--full` добавляет excerpt — по нему видно, о чём пост, без чтения целиком.

Для рассылки Псайко: посты, которые уже уходили в прошлых выпусках,
повторять не надо. Известные использованные — `/371`, `/282`, `/75`, `/294`
(проверь актуальность списка в проектных заметках). Отдавай подборку с
заголовком, ссылкой и одной строкой «почему этот пост здесь».

### 3. Похожие на конкретный пост

```bash
node cli.mjs similar <slug> --limit 10
```

Для блока «читайте также», сбора серий, поиска мест под перелинковку.
Работает мгновенно и бесплатно — вектор уже в индексе.

Slug можно давать частично: `similar mne-22-goda` найдёт `mne-22-goda-464`.

### 4. Аудит тегов

```bash
node cli.mjs tags                          # обзор: где тегов много, где мало
node cli.mjs tag <имя> --coherence         # связность конкретного тега
```

`--coherence` считает центроид векторов тега и cosine каждого поста к нему.
Средняя связность `0.809` (как у тега «медитация») — тег держит тему.
Посты внизу списка выбросов — кандидаты на снятие тега.

Низкая средняя связность означает, что тег стал зонтиком и его стоит
разделить. Прежде чем предлагать снять тег — прочитай пост через
`get <slug>`, потому что низкий cosine бывает и у поста, который к теме
относится, просто написан иначе.

## Границы

Индексируются только не-draft посты — файлы с `draft: true` пропускаются.
Поэтому число записей в индексе всегда меньше числа `.md` в папке, и это
норма, а не отставание. Точные цифры покажет `check`.

Ищется только то, что лежит локально в `~/cursor/pioblog/src/content/blog/`.
Если репо не склонировано или посты не подтянуты — искать не по чему.

Эмбеддинги стоят копейки: полный пересбор ~180 постов ≈ $0.004,
инкрементальный досбор — доли цента. Ключ `OR_LLM_API_KEY` лежит в
`mcp/blog-search/.env` (gitignored).

`index.json` — 5 МБ, gitignored, живёт только локально. В git его не
коммитить: раздует репо, а собирается он за секунды.

## Когда что-то не так

| Симптом | Причина и что делать |
|---|---|
| `нет OR_LLM_API_KEY в .env` | Ключ пропал из `.env`. Взять из GH-секретов репо (`OR_LLM_API_KEY`) |
| `индекса нет` | Первый запуск на машине: `node cli.mjs sync` |
| `embeddings 401/402` | Ключ OpenRouter истёк или кончился баланс |
| MCP-тулы отсутствуют | Норма, иди через CLI. Причина обычно — снесённые `node_modules` |
| Поиск не находит очевидный пост | Проверь `check` — возможно, пост в драфте, тогда он не в индексе |
