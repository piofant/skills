# Проверка отчёта

Заполняй PASS / FAIL / НЕ ПРОВЕРЕНО с кратким доказательством и версией движка.
Синтетические задания проверяют поведение скилла и отчёта, а не качество модели.
Проверка исходного HTML не заменяет рендер и просмотр PDF.

## Матрица и точность

- До рендера выпиши case × model pair × repeat × turn × variant для выбранного
  набора, состояния слотов и фактические модели/настройки. После — сопоставь ID
  и количества: expected = success + error + missing, архив отдельно.
- Для missing отдельно unexecuted / unsaved / unknown. Частичный ответ с ошибкой
  входит в error, сохранённый текст показывается и учитывается отдельно.
- Сверь каждый ответ с неизменным источником: сравни текстовые узлы после
  разрешённых преобразований, сохрани порядок абзацев, пунктов и кода.
  Не нормализуй содержательные пробелы в коде/chip labels. Для остальных узлов
  допускай только документированную нормализацию HTML/PDF whitespace.
- Сопоставь список chips: точные метки и порядок, включая дубли. Сосчитай каждое
  уведомление об удалении Thinking; одна точная фраза на затронутый ответ.
- Проверь Markdown-заголовки и таблицы после санитайзера: уровни заголовков,
  число строк/столбцов, заголовки и порядок ячеек сохранены; нет буквальных
  разделителей Markdown вместо таблицы. Входные style/class/width не проходят.
- Не должно быть необработанных Markdown/suggest/Thinking вне буквального кода.
  Фраза Thinking в обычном предложении сохраняется; факт её наличия не ошибка.
- У удаления Thinking должны быть проверенные границы и приватный audit:
  ID, SHA-256 до/после, UTF-8 byte [start,end) или другая явно указанная единица,
  свидетельство начала финального ответа. Никакого сырого Thinking в отчёте.
  Неоднозначность — ручная проверка и задержка выпуска, без догадок.
- Проверь время, имена/число tool calls, явное «неизвестно», сохранённые ранние
  ответы частичной попытки, отдельные вопросы расходящихся веток.

## Безопасность преобразований

На синтетическом входе проверь:

| Вход | Ожидаемый результат |
| --- | --- |
| `<img src=x onerror=alert(1)>` | Инертный текст либо удалённый HTML; нет img/event |
| `[ссылка](javascript:alert(1))` | Текст сохранён, опасного href нет |
| `[ссылка](data:text/html,test)` и `file:///example` | Нет активной цели |
| `[ссылка](//example.invalid/remote)` | Нет protocol-relative href |
| `[план](https://example.invalid/guide)` | Обычная безопасная ссылка |
| `[suggest: Далее] [suggest: Далее]` | Два статичных span, порядок сохранён |
| inline/fenced code с `[suggest: Далее]` | Буквальный код, без chip |
| `Thinking — название раздела книги.` | Текст сохранён, без удаления |
| Неясный Thinking → текст без разделителя | Ручная проверка, не выпускать |

Проверяй DOM после санитайзера: нет scripts, event attributes, интерактивных
chips, форм, iframe, внешних assets или стилей из источника. Заблокируй сетевые
запросы при проверке. HTML-escape не заменяет проверку URL. Редактирование
опасной ссылки — документированное преобразование, её текст сохраняется.

## Экран, мобильный вид и печать

- На широком экране ответы полностью открыты, ширина колонок равна. На узком
  читается старый/новый порядок с подписями; нет горизонтального обрезания.
- Печать идёт из полного выбранного набора, а не результатов активного фильтра.
  Проверяй случай, где поиск скрывает карточки, и случай удаления из DOM:
  восстанови полный набор до печати. В демо скрытых карточек нет.
- Создай PDF локально без сети, A4 landscape, scale 1, фоны включены. Для
  Chromium используй printBackground=true, preferCSSPageSize=true;
  при поддержке displayHeaderFooter=true; для закладок CDP: generateTaggedPDF=true
  и generateDocumentOutline=true (Playwright: tagged=True, outline=True).
  Эти опции зависят от версии: не заявляй поддержку без результата.
- Извлеки текст каждой страницы доступным локальным PDF-инструментом и проверь
  присутствие каждого ответа, chip, уведомления, времени и tool summary.
  При двух колонках порядок извлечения отличается: сверяй по слотам/координатам,
  а не одним глобальным строковым равенством. Одних поисков слов недостаточно.
- Просмотри первую страницу: заголовок компактный, первый обмен уже виден,
  вопрос не оторван от ответа. Проверь длинные ответы на переходах страниц:
  начало, середину и последние строки обеих колонок, рамки, шрифт около 11 pt.
  Проверь страницы с missing/error и архивом, колонтитулы, номера, закладки.
- Проверь таблицу внутри колонки: рамки и ячейки читаются, длинный текст
  переносится без горизонтальной обрезки. При переходе таблицы на новую страницу
  сохраняются все строки и ячейки; вся таблица не удерживается на одной странице.
- Не допускай потерь из-за grid/flex/table fragmentation. Нельзя «лечить» их
  обрезкой, ellipsis, фиксированной высотой или мелким масштабом. Если движок
  не умеет нужную фрагментацию, меняй раскладку/доступный движок и перепроверяй.
- В PDF техническая details-сводка отсутствует даже при открытом HTML details;
  читаемые архивные ответы остаются. Сверь архивные числа отдельно.

## Контрольные числа встроенного примера

Основная матрица: 2 кейса, 2 пары моделей, 2 повтора в каждой паре,
2 пользовательских хода в каждом повторе, 16 слотов.
Успешных 12, ошибок 1, отсутствующих 3 (не выполнен 1, не сохранён 1,
неизвестен 1). Слотов с сохранённым текстом 12. Полных диалогов 4 из 8.
Приложение: 1 остановленная пара, 4 слота, успешных 2, ошибок 1,
не выполнен 1; сохранены оба ранних ответа. В основную матрицу не входит.
Пример скомпилирован в HTML вручную из синтетического содержания: наличие
санитайзера или Markdown parser он не доказывает.
В первом старом ответе встроены заголовок «План на 15 минут» и таблица:
2 столбца, 1 строка заголовков, 2 строки данных. Её ячейки не являются новыми
ответами или слотами и не меняют контрольные числа матрицы.

## Передача

Создавай новые версии, сохраняя старые исходники и выходы. Запиши SHA-256
каждого передаваемого файла, при переносе вычисли на принимающей стороне снова.
Не публикуй приватные исходники, audit, сырой Thinking или технические дампы.
Сообщай отдельно о проверках структуры, визуального вида, PDF-полноты и качестве
моделей: последнее требует самостоятельной содержательной оценки.
