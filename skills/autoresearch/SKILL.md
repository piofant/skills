# Autoresearch — самоходная петля «измерь → измени → измерь → оставь лучшее»

Скилл превращает агента в автономный движок, который крутится сам, ведёт журнал и **никогда не останавливается до прерывания пользователем**. Один скилл — два режима:

- **Mode A — Metric-loop** — есть измеримая метрика (`./autoresearch.sh` печатает число). Цель: довести метрику до таргета. Цикл эксперимент → замер → keep/discard.
- **Mode B — Research-loop** — нет численной метрики, есть вопрос/тема. Цель: исчерпывающее покрытие. Цикл под-вопрос → поиск → чтение → верификация → синтез → поиск пробелов.

Выбор режима — по задаче: если можно написать скрипт, печатающий число → A. Если «исследуй / собери / разберись» → B. Можно совмещать (ресёрч-фаза кормит идеями metric-фазу).

---

## Файлы состояния (в рабочей папке проекта)

| Файл | Роль | Кто пишет |
|------|------|-----------|
| `autoresearch.md` | Цель, метрика, правила, off-limits, «что уже пробовали» | агент ведёт |
| `autoresearch.jsonl` | Машинный журнал прогонов (1 строка = 1 эксперимент) | агент аппендит |
| `autoresearch.sh` | (Mode A) раннер: печатает `METRIC <name>=<value>` | агент/юзер |
| `autoresearch.ideas.md` | Бэклог гипотез для следующих раундов | агент/юзер |
| `.autoresearch-off` | Sentinel: если файл есть — петля выключена | стоп-механизм |

Наличие `autoresearch.md` (и отсутствие `.autoresearch-off`) = «петля активна». Хук-напоминание (`assets/autoresearch-context.sh`, событие `UserPromptSubmit`) при активной петле подмешивает в каждое сообщение reminder «ты в петле, не останавливайся». Хук опционален — петлю можно вести и без него, просто следуя этому SKILL.

## Активация

1. Создай в рабочей папке `autoresearch.md` из шаблона `assets/autoresearch.md.tmpl` — заполни Objective / Metric / Files in Scope / Off Limits / Constraints.
2. **Mode A:** напиши `autoresearch.sh` (шаблон `assets/autoresearch.sh.tmpl`), убедись что `./autoresearch.sh` печатает строку вида `METRIC primary=<число>`. Сделай первый прогон = baseline.
3. (Опц.) Подключи фоновый reminder-хук — один раз на проект:
   ```bash
   bash <SKILL_DIR>/scripts/install-hook.sh   # добавит UserPromptSubmit hook в ./.claude/settings.json
   ```
4. Объяви метрику в журнале (первая строка `autoresearch.jsonl` — config) и залогируй baseline.

---

## Mode A — Metric-loop (главный режим)

Жёсткий протокол одного раунда. Повторять до таргета или прерывания:

1. **HYPOTHESIS** — выбери ОДНО маленькое явное изменение (из `autoresearch.ideas.md` или придумай). Малые шаги = regression-friendly.
2. **APPLY** — внеси изменение только в файлы из «Files in Scope». Ничего вне зоны.
3. **MEASURE** — `./autoresearch.sh`, распарси `METRIC primary=...` (+ вторичные).
4. **DECIDE** по `bestDirection`:
   - метрика улучшилась → **keep** (закоммить, обнови «What's Been Tried»).
   - не улучшилась / регресс → **discard** (откати изменение: `git checkout -- <files>`).
5. **LOG** — добавь строку в `autoresearch.jsonl` (см. схему ниже) через `scripts/ar-log.sh`.
6. **GUARD** — никогда не регрессируй уже достигнутое; если упёрся — генери новый класс гипотез, не повторяй проваленные.
7. **LOOP** — назад к шагу 1. Стоп только при: метрика ≥ target N раундов подряд, явный `.autoresearch-off`, или прерывание пользователя.

Сообщения пользователя во время петли = **steers**: доделай текущий эксперимент, залогируй, затем учти идею в следующем раунде. Не бросай раунд на полпути.

### Схема `autoresearch.jsonl`
Первая строка — конфиг, дальше по строке на прогон:
```json
{"type":"config","name":"my-loop","metricName":"pass","metricUnit":"items","bestDirection":"higher"}
{"run":1,"commit":"3776e92","metric":5,"metrics":{"aggregate":4.88},"status":"keep","description":"baseline","timestamp":1778753940}
{"run":2,"commit":"694d181","metric":6,"metrics":{"aggregate":4.97},"status":"keep","description":"rule 12 anti-template","timestamp":1778754121}
{"run":3,"commit":"...","metric":5,"metrics":{},"status":"discard","description":"length cap 180 — регресс","timestamp":...}
```
`bestDirection`: `"higher"` (точность, pass-count) или `"lower"` (доля ИИ, latency, loss).

Логирование одной командой:
```bash
bash <SKILL_DIR>/scripts/ar-log.sh --run 4 --metric 7 --status keep --desc "lore-specific openers"
```

## Mode B — Research-loop

Когда метрика не численная. Тот же дух «не останавливайся», но единица прогресса — закрытый под-вопрос, а `autoresearch.md` держит карту покрытия.

Раунд:
1. **DECOMPOSE** — разбей тему на под-вопросы; держи список в `autoresearch.md` со статусом `[ ]/[~]/[x]`.
2. **SEARCH** — возьми самый ценный незакрытый под-вопрос; ищи (WebSearch / WebFetch / MCP: codesearch, intrasearch, telegram-remote и т.п.).
3. **READ & EXTRACT** — вытащи факты с источниками (url/путь).
4. **VERIFY** — адверсариально перепроверь ключевые утверждения вторым независимым источником/поиском; помечай уверенность.
5. **SYNTHESIZE** — допиши секцию в `report.md` (или целевой документ).
6. **GAP-SCAN** — что осталось непокрыто / непроверено / противоречиво → новые под-вопросы в backlog.
7. **LOOP** — пока остаются открытые под-вопросы выше порога важности. Лог в `autoresearch.jsonl` (`metricName:"open_questions"`, `bestDirection:"lower"`).

Совмещение с Mode A: research-раунды наполняют `autoresearch.ideas.md` гипотезами для metric-петли.

## Остановка
- `touch .autoresearch-off` — мягкий стоп (петля видит sentinel и выходит).
- Удалить/переименовать `autoresearch.md` — петля считается неактивной.
- Достигнут таргет, удержан N раундов — объяви результат и остановись сам.

## Анти-паттерны
- ❌ Большие изменения за раунд — нельзя атрибутировать эффект, легко регрессировать.
- ❌ Менять файлы вне «Files in Scope» / трогать раннер ради красивого числа (метрик-хакинг).
- ❌ Бросать эксперимент недозамеренным из-за нового сообщения юзера.
- ❌ Повторять уже проваленную гипотезу.
- ❌ Останавливаться «потому что кажется хватит» без таргета или прерывания.

## Связанные
- `ralph-loop` — дожать ОДНУ задачу по фиксированному промпту (без метрики/журнала).
- `/research`, `/deep-research` — одноразовый ресёрч-отчёт без бесконечной петли.
- `diploma-antiplag` — реальный кейс Mode A: довод ИИ-контента ВКР 25.5%→0% петлёй против нейродетектора.
