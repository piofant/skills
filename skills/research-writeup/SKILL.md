# Research Writeup

Оформление ресёрч-отчёта, которому можно верить.

Соседние скиллы закрывают другое и здесь не дублируются:

- `report-styling` — визуал: активные заголовки, чарты, палитра, caption'ы. **Использовать вместе с этим скиллом.**
- `research-deep` / `research-report` — пайплайн «аутлайн, агенты, сводка».
- `md-to-pdf-deck` — экспорт в PDF.

Этот скилл — про **доказательную часть**. Про то, чем отчёт, которому верят, отличается от пересказа.

---

## Принцип 0 — премисса запроса может быть ложной, и это главный результат

Самое ценное, что может дать ресёрч, — сказать «то, что вы просили найти, не существует».

Запрос часто содержит встроенное допущение: «найди, как они использовали фреймворк X». Если они его не использовали — это не провал поиска. Это находка, и она важнее всего остального, потому что иначе на ложном допущении построят продукт.

**Если премисса не подтвердилась — раздел 0 отчёта, до всего остального.**

```markdown
## 0. Поправка к постановке задачи

Исходный запрос предполагал, что разработчики зафиксировали профиль личности
по шкалам Big5.

**Это не подтверждается.** Полный текст обеих статей прогрепан на термины:

| Термин | Вхождений в [CL2020] | Вхождений в [Eliza2018] |
|---|---|---|
| Big Five / OCEAN | 0 | 0 |
| agreeableness | 0 | 0 |

Что они делали вместо — раздел 1.
```

Обратите внимание на последнюю строку. Опровергнуть мало — надо сразу дать то, что там на самом деле. Иначе отчёт читается как «ничего не нашёл».

## Принцип 1 — проверяй первоисточник сам, а не пересказ

Субагенты, обзоры и вторичные статьи **систематически врут в деталях**: путают год, приписывают цифру не тому источнику, пересказывают чужой пересказ.

Любое утверждение, на котором держится вывод, проверяется по оригиналу руками:

```bash
curl -sL -o paper.pdf https://arxiv.org/pdf/XXXX.XXXXX
pdftotext -layout paper.pdf paper.txt
grep -n -i -B3 -A6 "ключевая фраза" paper.txt
```

Что это ловит на практике:

- цифра из таблицы, которую пересказчик округлил или приписал не той модели;
- «в статье сказано X» — а там сказано ровно наоборот;
- термин, которого в статье нет вообще (см. Принцип 0).

**Правило:** если утверждение попадёт в резюме отчёта — цитата под него добыта из оригинала. Не из аннотации, не из обзора, не из ответа агента.

Если PDF не парсится через WebFetch (частый случай) — скачать и распарсить локально. Бинарь через WebFetch читать бесполезно.

## Принцип 2 — таблица статуса проверки, включая опровергнутое

Отчёт заканчивается таблицей, где у каждого несущего утверждения есть статус. **Опровергнутые строки не удаляются — они самые ценные.**

```markdown
| Утверждение | Статус | Основание |
|---|---|---|
| 660 млн активных пользователей | подтверждено | [CL2020], дословно |
| Image Commenting удваивает CPS | подтверждено | [CL2020], A/B-тест |
| **Big5 использовался разработчиками** | **опровергнуто** | 0 вхождений в полном тексте |
| **Анализ аватарок пользователей** | **не найдено** | подтверждено только комментирование присланных картинок |
| 60+ обращений в месяц | вторичный источник | не первоисточник, доверять осторожно |
```

Четыре статуса, и путать их нельзя:

- **подтверждено** — есть дословная цитата из первоисточника;
- **опровергнуто** — первоисточник говорит обратное;
- **не найдено** — отсутствие доказательств, а не доказательство отсутствия. Так и писать;
- **вторичный источник** — есть, но не из первых рук. Помечать явно.

## Принцип 3 — цитата без перевода не работает

Стена английского в русском отчёте — это место, где читатель перестаёт читать. Особенно стейкхолдер.

Схема на каждую цитату: **сначала мысль по-русски, потом цитата как доказательство, потом перевод.**

```markdown
**Что делали они.** Запущенный скилл держит разговор. Перебить его непросто —
это сознательное решение.

> «To ensure a smooth conversation, we avoid switching among different skills
> too often. We prefer keeping the running skill activated until it terminates»
>
> *(«Чтобы разговор шёл гладко, мы избегаем частого переключения между скиллами.
> Мы предпочитаем держать запущенный скилл активным, пока он сам не завершится»)*
```

Плохо: заголовок «М2. Иерархическая политика», сразу абзац английского, потом «что дало».
Читатель не знает, зачем ему это, и уходит.

**Цитата — доказательство уже сказанного, а не способ что-то сказать.**

## Принцип 4 — структура переноса: четыре плана на каждую механику

Ресёрч чужого продукта пишется не как пересказ, а как **инструкция к переносу**. На каждую механику четыре блока, всегда в одном порядке:

```markdown
## 2. Скилл не должен слетать от одного случайного слова

**Что делали они.** [объяснение по-русски + цитата с переводом]

**Что дало.** [цифра. Если цифры нет — так и сказать]

**Что было у нас.** [честно, с конкретикой: файл, поведение, известный баг]

**Что сделали.** [конкретное решение или «пока не сделали, потому что…»]
```

Без блока «что у нас» получается реферат. Без блока «что сделали» — благие намерения.

В конце — сводная таблица «механика / что дала / куда легла», чтобы можно было читать только её.

## Принцип 5 — числа с колонкой источника

Каждое число в отчёте имеет источник. Всегда. Иначе через месяц никто не вспомнит, откуда взялось «23», и оно начнёт жить своей жизнью.

```markdown
| Показатель | Значение | Источник |
|---|---|---|
| Активных пользователей | 660 млн | [CL2020] |
| Средний CPS (6-е поколение) | 23 | [CL2020] |
| CPS человеческого разговора | 9 | [CL2020] |
| Обучающий сет Image Commenting | 28 млн × 6 | [CL2020] |
```

Расхождения между источниками — **показывать, а не усреднять**. Если статья 2018 говорит «19-летняя», а статья 2020 — «18-летняя», это находка (персона дрейфует), а не шум.

## Принцип 6 — раздел «что это не решает»

Отчёт без границ применимости читается как продажа. Раздел обязателен, ближе к концу:

```markdown
## Что это не решает

**Скилл загружен не равно модель ему следует.** На E2E видно: скилл на месте,
лог доказывает, а модель отвечает лениво. Механика доставки инструкций
починена, дисциплина модели — отдельная задача.

**Бюджеты взяты по аналогии** с Dialogflow, а не из наших данных.
```

Сюда же — открытые вопросы и главный блокер, если он есть. Блокер выносить явно, а не прятать в списке.

---

## Принцип 7 — анти-примеры сильнее примеров

Показать, как надо, — половина дела. Показать, как ломается, — вторая половина, и её обычно пропускают.

```markdown
| Сигнал | Провал | Цель |
|---|---|---|
| Досмотрел «Твин Пикс» | «Сериал Линча 1990 года» | «Ты дошёл до серии с карликом?» |
```

И отдельно — **критерий приёмки одной фразой**, который можно применить не думая:

> Если реплику можно напечатать на обложке диска — она провалена.

Такая фраза переживает отчёт. Таблицы забудут, критерий запомнят.

## Принцип 8 — резюме отвечает на «что изменилось», а не «что я делал»

Первый экран — это то, ради чего человек открыл документ. Не введение, не методология.

```markdown
## Резюме

Шесть выводов, ради которых стоит читать дальше.

1. **Big Five в XiaoIce нет.** Ни в одной из двух статей команды термин не
   встречается ни разу. Личность зафиксирована иначе — и способ интереснее
   психометрики.

2. **Персона — статистический слепок «желательных» пользователей.** [...]
```

Каждый пункт — **утверждение**, а не тема. «Про метрики» — это тема, читать невозможно. «CPS упёрся в потолок 23 ещё в 2016 году» — утверждение.

Правило: если пункт резюме можно оспорить — он написан правильно. Если нет — это оглавление, а не резюме.

## Принцип 9 — связывать доки цепочкой

Отчёт-сирота, на который ниоткуда нет ссылки, не существует. Проверять механически:

```bash
grep -rl "имя-файла.md" docs/ | grep -v "^docs/имя-файла.md$" | wc -l
```

Ноль — значит сирота. В шапке первого дока цепочки — навигация:

```markdown
> **Это первый док цепочки.** Дальше: [механики](...), [дизайн](...),
> [что уехало в прод](...).
```

И проверять относительные ссылки, они ломаются молча:

```python
import re, pathlib
for m in re.finditer(r'\[([^\]]+)\]\((?!https?:|#)([^)]+)\)', p.read_text()):
    if not (p.parent / m.group(2)).resolve().exists():
        print(f"БИТАЯ: {p} -- {m.group(2)}")
```

## Структура отчёта целиком

```
Заголовок + подзаголовок (что это и для кого)
Дата / задача / метод (три строки, не абзац)
Навигация по цепочке доков

Резюме — N выводов-утверждений, каждый оспорим
Что забрать в продукт — одним абзацем

0. Поправка к постановке задачи  <- только если премисса ложна
1..N. Механики (что делали / что дало / что у нас / что сделали)
   Числа — таблицами с источником
   Цитаты — с переводом
   Чарты — по report-styling

Что это не решает + открытые вопросы + блокер

Приложение А. Статус проверки утверждений  <- включая опровергнутые
Приложение Б. Библиотека примеров и анти-примеров
Приложение В. Источники (первоисточники отдельно от вторичных)
```

## Грабли

**Верить субагенту.** Агент вернул claim с цитатой — это не значит, что цитата есть в оригинале. Проверять несущие руками.

**Прятать опровергнутое.** Соблазн убрать из отчёта то, что не подтвердилось, потому что «не получилось». Ровно наоборот: опровержение экономит месяцы.

**Усреднять расхождения.** Два источника дают разные цифры — показать оба и объяснить, а не взять среднее.

**Писать «не найдено» как «нет».** Отсутствие доказательств — не доказательство отсутствия. Формулировка «в опубликованных материалах не найдено» честнее, чем «этого не было».

**Стена английского.** Даже одна цитата без перевода — это место, где стейкхолдер закрывает документ.

**PDF-лонгрид упирается в потолок.** У формата PDF предел высоты страницы около 5080 мм. Документ с картинками легко перерастает его и разваливается на две страницы. Лечится шириной картинок (`max-width: 40%`), а не высотой страницы.
