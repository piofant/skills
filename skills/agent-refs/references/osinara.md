# Осинара — карта кода (nyxandro/osinara)

Снято с коммита: `251a28f` (2026-11-22). Пути — от корня репо. Копия: `~/.cache/agent-refs/osinara`.

## Что это
Self-hosted агент одной семьи, живёт только в Telegram: помнит контекст, ставит напоминания и сценарии по расписанию, работает с файлами, Google Workspace и браузером в Docker-sandbox. Главная идея: права определяет проверенный апдейт Telegram и база, а не текст промпта. TypeScript (Node 24), своё ядро на Vercel AI SDK 7 (часть кода адаптирована из `vercel/eve` 0.40.0), PostgreSQL 17 + pgvector, локальные эмбеддинги multilingual-e5-small через HF TEI. Модель по умолчанию `deepseek-v4-flash` (`config/agent-model-providers.json`), голос Groq Whisper, озвучка ElevenLabs. Docker Compose (`compose.production.yaml`), образы из CI в GHCR, `install.sh` + CLI `osinara`, автообновление после подтверждения владельца в Telegram. Вход — `agent/main.ts`. ~115k строк TS, ~107k строк тестов, 158 SQL-миграций.

**Лицензия:** файла LICENSE нет, в `package.json` только `"private": true`. Под Apache-2.0 только адаптированные файлы eve (`THIRD_PARTY_NOTICES.md`). Остальной код без явной лицензии — копировать дословно нельзя, повторяем приёмы своими словами.

## Архитектура за 1 минуту
1. Webhook `/v1/telegram` → `agent/runtime/telegram/telegram-channel.ts:120`, проверка secret token — `verify.ts:62`.
2. Устойчивый приём `agent/lib/telegram-durable-ingress.ts:210`: апдейт сохраняется в Postgres до ACK, FIFO по чату и топику; личные сообщения подряд склеиваются после 2 с тишины (`telegram-private-burst.ts:64`, `config.ts:87`); голос расшифровывается до хода (`groq-voice-transcription.ts:147`); хвосты добирает `scripts/telegram-ingress-worker.ts`.
3. Граница авторизации `agent/lib/telegram-on-message.ts:75`: сообщение группы пишется в журнал и ставится в очередь тихого разбора памяти; сигнал обращения — `telegram-message-policy.ts:110`; права — `family-access.ts:77`.
4. Сессия и ход: `agent/runtime/telegram/telegram-dispatch.ts:207` → `agent/runtime/dispatch.ts:48` (recovery, runner-lock).
5. Цикл: `agent/runtime/turn/run-turn.ts:416` (`runStep`), `:554` (`runTurn`). Резолверы инструкций (`agent/agent.ts:113`) подтягивают память и режим; инструменты собираются заново на каждом шаге (`agent/tools/capabilities.ts:62`); компакция (`run-turn.ts:290`); вызов модели (`model-call.ts:294`). Каждый шаг журналируется в одной транзакции.
6. Доставка: `agent/channels/telegram.ts` → `agent/lib/telegram-final-delivery.ts:41`; молчание — маркер `<empty-delivery/>` (`runtime/turn/step-history.ts:22`).
7. Фон: минутный cron (`agent/runtime/scheduler.ts`) — напоминания, сценарии, разбор памяти, обновления, recovery (`agent/application.ts:246-261`).

## Сильные практики
1. **Гейт соседей при записи** — `agent/lib/memory-neighbour-gate.ts:1-46,92`. Есть похожая запись (cosine ≥ 0.93) — запись блокируется, модели показывают соседей; пройти можно, только явно назвав их в `distinctFrom` или `replaces`. Код сам ничего не сливает, порог измерен на проде. Перенос: средне.
2. **Слот атрибута с версиями** — `memory-attribute-slot.ts:167`, `migrations/111_memory_attribute_slot.sql`. Новое значение («город», «работа») переводит старое в superseded со ссылкой на сменщика. Перенос: низко.
3. **Забывание как множитель с полом** — `agent/lib/memory-forgetting.ts:1-69`: `floor + (1-floor)·exp(-age/S)`, S = `1+ln(1+n)` от числа использований, разный срок для эпизодов и фактов. Перенос: низко.
4. **Фильтр small talk перед retrieval** — `memory-small-talk.ts:95`: закрытый словарь приветствий и благодарностей отключает автовыборку памяти. Перенос: низко.
5. **Права вне промпта** — `family-access.ts:77`, `tools/capabilities.ts:62`: scopes и инструменты из проверенного апдейта, политика перечитывается каждый шаг; prompt injection не расширит права. Перенос: средне.
6. **Протокол молчания в группе** — `lib/prompt/group-fragments.ts:45-80`, `step-history.ts:22`: четыре исхода, `triggeredBy` в контексте, маркер `<empty-delivery/>`, примеры «обсуждают меня» vs «обращаются ко мне». Перенос: низко.
7. **Тихий фоновый разбор памяти групп** — `lib/memory-review/memory-review-prompt.ts:16`, `schedules/memory-review-dispatch.ts`: пачки до 50 сообщений, отдельный ход с одним scope и минимумом инструментов, сообщения — недоверенные данные. Основной ход не тратит время на память. Перенос: средне.
8. **Durable ingress + журнал ходов** — `telegram-durable-ingress.ts:1-18`, `run-turn.ts:1-25`: рестарт не теряет и не дублирует ответы. Перенос: высоко.
9. **Retrieval-эвалы как гейт релиза** — `memory-retrieval-eval-v3/index.ts`, `ci-release.yaml:30-43`: фикстуры с baseline (включая известные провалы), отдельный корпус на утечки между группами. Перенос: средне.
10. **Директива использования памяти** — `lib/memory-usage-directive.ts:1-25`: модель служебной строкой называет записи, на которые опёрся ответ. На проде до этого счётчик подкрепления стоял на нуле у 1456 записей из 1465. Важно место инструкции: внутри блока режима — 1 срабатывание из 36, обязательное напоминание сразу после записей — 34 из 36. Пустой список отличается от молчания. Перенос: низко.
